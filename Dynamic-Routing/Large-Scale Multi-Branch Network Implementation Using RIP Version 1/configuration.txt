2. IMPORTANT RIPv1 ADDRESSING CORRECTION
====================================================================

The screenshot originally labels:
  HQ LAN:         172.16.1.0
  Data Center LAN:172.16.2.0

With classful Class B addressing, both are part of the same
172.16.0.0/16 major network. They are on different routers with
other networks between them. RIPv1 does not carry subnet masks and
does not support discontiguous subnetting.

To make this RIPv1 lab work reliably, use a different Class B major
network for the Data Center:
  Data Center gateway: 172.17.2.1
  Server0:             172.17.2.10
  Server1:             172.17.2.11
  Server2:             172.17.2.12
  Mask:                255.255.0.0

This is the one intentional addressing change from the screenshot.
All server host numbers remain the same.

4. INTERFACE IP CONFIGURATION
====================================================================

IMPORTANT:
The screenshot does not show the exact interface names for every
cable. Identify the ports used in your own Packet Tracer file with:

  show ip interface brief

The interface names below are EXAMPLES. Map each IP address to the
actual connected port. Use a separate interface for each LAN/WAN link.

EXAMPLE – LAN interface:
  enable
  configure terminal
  interface gigabitEthernet 0/0
   ip address 192.168.1.1 255.255.255.0
   no shutdown
  exit

EXAMPLE – WAN serial interface:
  interface serial 0/0/0
   ip address 10.0.12.1 255.0.0.0
   no shutdown
  exit

On the DCE end of a serial link only, if Packet Tracer requires clock:
  clock rate 64000

Do not configure the same IP address on more than one interface.

7. VERIFICATION COMMANDS
====================================================================

Run on every router:

  show ip interface brief
  show ip protocols
  show ip route
  show running-config

Expected:
  - Connected interfaces show up/up.
  - show ip protocols identifies RIP and version 1.
  - Remote routes appear with the code R in show ip route.
  - Each router learns remote LANs and WAN networks through RIP.

From PCs:
  ping <remote-PC-IP>
  ping 172.17.2.10
  ping 172.17.2.11
  ping 172.17.2.12

Use tracert from a PC to observe the routed path:
  tracert 192.168.6.10

8. PRACTICAL TEST SCENARIOS
====================================================================

1. Ping from Branch A to Branch F.
2. Ping from Branch C to all three Data Center servers.
3. Ping from Branch D to an HQ PC.
4. Run tracert between two remote LANs and observe the router path.
5. Shut down one WAN interface with:
     configure terminal
     interface <WAN-interface>
     shutdown
   Wait for RIP to reconverge, then test the destination again.
6. Restore the interface:
     no shutdown
7. Check the routing table again:
     show ip route

====================================================================
9. TROUBLESHOOTING CHECKLIST
====================================================================

- Check IP address and subnet mask on every router interface.
- Check that every router interface is enabled with no shutdown.
- Check serial DCE clock rate if required.
- Check PC/server default gateways.
- Check that each WAN link has a unique Class A major network.
- Check RIPv1 is enabled on every router.
- Check each router has network statements for its directly connected
  networks.
- Check for overlapping or duplicated IP subnets.
- Remember that a successful ping needs both a forward route and a
  return route.

====================================================================
10. RIPv1 TECHNICAL NOTES
====================================================================

- RIPv1 is a classful distance-vector routing protocol.
- RIPv1 does not include subnet masks in routing updates.
- RIPv1 does not support VLSM or CIDR.
- Class A default mask: 255.0.0.0.
- Class B default mask: 255.255.0.0.
- Class C default mask: 255.255.255.0.
- RIP uses hop count as its metric.
- Maximum usable hop count is 15; 16 means unreachable.
- RIPv1 sends periodic broadcast routing updates.
- RIPv1 does not support authentication.
